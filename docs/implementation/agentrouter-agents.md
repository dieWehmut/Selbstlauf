# AgentRouter agent coverage

Audited against the live [AgentRouter documentation](https://agentrouter.org/docs/) on 2026-11-11. Its navigation has 17 tool guides: four VS Code extension guides, eight CLI guides, and five desktop guides. Claude Code's CLI and extension guides share one product identity. The homepage additionally names Gemini CLI.

The shared source of truth is `apps/cli/src/agents/registry.ts`. `/api/agents/catalog` exposes every product, including unavailable local tools; the local-environment report lists only CLIs. `installUrl` and `docsUrl` belong to the publisher, while `guideUrls` point to AgentRouter. Missing commands are never silently replaced with another tool. Desktop and extension entries currently open their installation/integration guides; the PTY API rejects them even when a caller supplies a command override.

Existing Gemini CLI, Grok Build, DeepSeek Harness, Antigravity, Cursor, shell and custom presets are retained. Cline and Kilo expose real publisher CLIs in addition to the extension workflows described by AgentRouter. There are 24 launch catalog entries, including the two WorkBuddy editions, and 13 CLIs in the environment catalog.

Both WorkBuddy websites identify Tencent Cloud as the publisher. Their official pages explicitly set `IS_INTERNATIONAL_EDITION` to false and true respectively. The original `workbuddy` ID is retained for the China installer, while `workbuddy-intl` selects the international installer. Both are desktop entries and reject PTY launches, including command overrides. The publisher's distinct `WorkBuddyAI.exe` executable identifies the international edition in process monitoring. A shared `WorkBuddy.exe` name continues to use the product-level WorkBuddy identity; an edition string in argv alone cannot prove the installed region. Installation detection verifies each edition's executable path independently and does not alter existing tool settings.

Process identity uses the resolved executable and the actual interpreter entry. Prompt text, preload/eval code, renamed process titles and runtime option values cannot supply an agent identity. Claude, Codex and DSH scripts must match their real CLI entries; arbitrary files elsewhere in their packages do not qualify. Working-directory options are read only from the agent's own arguments, after interpreter options and the executed script. Unknown interpreter options are rejected when their argument boundaries cannot be established. These boundaries are covered in `apps/cli/test/process-identity.test.ts`, alongside existing discovery and controller regressions.

The AgentRouter guide pages define configuration examples and protocol choices; the application links to these rather than overwriting the user's existing credentials or provider configuration. OpenAI-compatible providers generally use `https://agentrouter.org/v1`; Anthropic-compatible providers use `https://agentrouter.org`. Models are dynamic and must be selected from the current service console. Local availability proves only that a command can be resolved; it does not imply that authentication, model access, or a gateway is configured.

Official npm metadata was checked directly at `registry.npmjs.org/<package>/latest` for package identity, executable mapping and repository. Qwen, Pi, Hermes and OpenClaw installation commands were cross-checked against their current publisher READMEs. Pi's old `@mariozechner/pi-coding-agent` package remains a distinct legacy distribution; the current AgentRouter guide explicitly names `@earendil-works/pi-coding-agent`. Icons and their publisher provenance are tracked separately in `apps/web/public/tool-icons/sources.json`.

Verification is in `apps/cli/test/agent-registry.test.ts` and the environment tests: all 17 guide URLs, complete product identities, absent CLI display, publisher links, desktop/extension rejection, OpenClaw default/override arguments through a real PTY, standalone version parsing, new package whitelist, and refusal of automatic Hermes installation.
